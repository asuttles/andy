ANDY COMPILER

Andy's ALGOL-- to +Wasm+ c Compiler written in Common Lisp.

* Original Goals
- Implement a PL/0 compiler with a real AST representation.
- Support extensions later (floats, strings, richer functions).
- Target WebAssembly, for a basic stack-based VM backend.
* References
- Wirth, Niklaus. Compiler construction. Germany: Addison-Wesley, 1996.

* Original PL/0 EBNF
#+begin_src pascal

  program   = block "." .

  block     = [ "const" ident "=" number { "," ident "=" number } ";" ]
              [ "var" ident { "," ident } ";" ]
              { "procedure" ident ";" block ";" }
              statement .

  statement = [ ident ":=" expression
              | "call" ident
              | "begin" statement { ";" statement } "end"
              | "if" condition "then" statement
              | "while" condition "do" statement ] .

  condition = "odd" expression
             | expression ( "=" | "#" | "<" | ">" ) expression .

  expression = [ "+" | "-" ] term { ( "+" | "-" ) term } .

  term       = factor { ( "*" | "/" ) factor } .

  factor     = ident
             | number
             | "(" expression ")" .

  ident  = letter { letter | digit } .
  number = digit { digit } .
  letter = "a" | "b" | ... | "z" .
  digit  = "0" | "1" | ... | "9" .
    
#+end_src

* Andy EBNF
#+begin_src ebnf

  (* --- Lexical Elements --- *)
  letter        = "A" | ... | "Z" | "a" | ... | "z" ;
  digit         = "0" | ... | "9" ;
  identifier    = letter { letter | digit | "_" } ;
  integer       = digit { digit } ;
  float         = digit { digit } "." digit { digit } ;
  number        = float | integer ;
  string-lit    = '"' { printable-character - '"' } '"' ;
  comment       = "//" { any-character - newline } newline ;

  (* --- Program --- *)
  program       = "program" program-type block "." ;
  program-type  = "int" | "float" | "void" ;
  block         = [ constant-declarations ]
                  { variable-declaration }
                  { function-declaration }
                  statement ;

  (* --- Declarations --- *)
  constant-declarations = "const" typed-const { "," typed-const } ";" ;
  typed-const           = type identifier "=" literal ;

  variable-declaration  = type var-list ";" ;
  var-list              = var-decl { "," var-decl } ;
  var-decl              = identifier [ "[" integer "]" ] ;
  type                  = "int" | "float" | "string" ;
  literal               = number | string-lit ;

  (* --- Functions --- *)
  function-declaration  = "fun" identifier "(" [ parameter-list ] ")"
                          [ ":" type ]
                          block ";" ;
   
  parameter-list        = parameter { "," parameter } ;
  parameter             = type identifier ;

  (* --- Statements --- *)
  statement =
        assignment
      | call
      | compound-statement
      | if-statement
      | while-statement
      | for-statement
      | switch-statement
      | break-statement
      | return-statement
      | ε ;

  assignment            = identifier [ "[" expression "]" ] ":=" expression ";" ;
  call                  = identifier "(" [ argument-list ] ")" ";" ;
  argument-list         = expression { "," expression } ;

  compound-statement    = "begin" statement { statement } "end" ;
  break-statement       = "break" ";" ;
  return-statement      = "return" [ expression ] ";" ;


  (* --- Flow Control --- *)
  if-statement          = "if" condition "then" statement
                          [ "else" statement ] ;

  while-statement       = "while" condition "do" statement ;

  for-statement         = "for" "(" [ assignment ] ";"
                                   [ condition ] ";"
                                   [ assignment ] ")"
                          statement ;

  switch-statement      = "switch" "(" expression ")"
                          { case-clause }
                          [ default-clause ]
                          "end" ;

  case-clause           = "case" integer ":" { statement } ;
  default-clause        = "default" ":" { statement } ;
         

  (* --- Conditions --- *)
  condition = expression relop expression ;
  relop     = "=" | "≠" | "<" | "≤" | ">" | "≥" ;

    
  (* --- Expressions --- *)
  expression            = logical-term { ("or" | "xor") logical-term } ;
  logical-term          = logical-factor { "and" logical-factor } ;
  logical-factor        = simple-expression [ relop simple-expression ] ;

  relop                 = "=" | "≠" | "<" | "≤" | ">" | "≥" ;

  simple-expression     = term { ("+" | "-") term } ;
  term                  = factor { ("*" | "/") factor } ;

  factor                = identifier [ "[" expression "]" ]
                        | number
                        | string-lit
                        | "(" expression ")"
                        | ("+" | "-" | "not") factor ;
#+end_src
* Andy's WASM Runtime Memory Model
** Strategy

|-------------------+--------------------------------------------------------------------------------------|
| Concept           | Purpose                                                                              |
|-------------------+--------------------------------------------------------------------------------------|
| Constants         | Immutable string and numeric literals emitted by the compiler.                       |
| Globals / statics | Variables with global scope that persist across functions.                           |
| Runtime headers   | Fixed metadata for WASI syscalls (like fd_write structs, nwritten count).            |
| Runtime buffers   | Scratch areas for formatting output or temporary conversions.                        |
| Heap              | Dynamic allocations that grow upward.                                                |
| Stack             | (Optional) language-managed stack that grows downward from the top of linear memory. |
|-------------------+--------------------------------------------------------------------------------------|

** Map
|----------------------------+-----------+---------+-----------+---------+----------+------------------------------------------------------------------------------|
| Region                     | Hex Start | Hex End | Dec Start | Dec End | Growth   | Purpose / Notes                                                              |
|----------------------------+-----------+---------+-----------+---------+----------+------------------------------------------------------------------------------|
| Constant strings / data    |    0x0000 |  0x03FF |         0 |    1023 | none     | Immutable data: string literals, "constant" values emitted by compiler.      |
| Globals / static variables |    0x0400 |  0x07FF |      1024 |    2047 | none     | Global/static vars used by all procedures. Assigned fixed offsets.           |
| Runtime headers / sys IOVs |    0x0800 |  0x08FF |      2048 |    2303 | none     | Fixed addresses for WASI fd_write structs, iovec tables, nwritten ptrs, etc. |
| Runtime buffers (scratch)  |    0x0900 |  0x0FFF |      2304 |    4095 | none     | Temporary space for print_i32, string building, etc.                         |
|----------------------------+-----------+---------+-----------+---------+----------+------------------------------------------------------------------------------|
| Heap (dynamic allocations) |    0x1000 |   ↑ ↑ ↑ |      4096 |   ↑ ↑ ↑ | upward   | Grows upward as dynamic memory is allocated (e.g., arrays, strings).         |
| Stack (language-managed)   |    0xF000 |   ↓ ↓ ↓ |     61440 |   ↓ ↓ ↓ | downward | Grows downward for local call frames or temporaries.                         |
|----------------------------+-----------+---------+-----------+---------+----------+------------------------------------------------------------------------------|

* C Backend Notes
  + Decided to try out a C Backend to maximize flexibility
  + Some backend tools to explore:
    - clang -Wall -Wextra -Wpedantic -Werror
    - explore: valgrind and ASan/UBSan
    - explore: clang-format (using emacs)
    - godbolt.org: explore how compiled c lowers to assembly language
  + To squeeze more optimization out of clang:
    - Use -O3 or -Ofast
    - Enable LTO: -flto
    - Avoid pointer aliasing where possible (restrict, clear ownership)
    - Prefer structs over pointer-heavy graphs
    - Keep control flow explicit and simple
  + How the Compiler Uses The Runtime
    - Emit #include "andy.h"
    - Allocates heap-allocated data (strings/arrays) via the arena
    - Uses runtime printing functions
    - Uses runtime error functions

* Project Ideas for Andylang
** Networking Experiments for Andy Language Runtime

*** Goal
Learn BSD socket programming and implement networking primitives for the Andy programming language runtime (transpiles to C).

Primary reference:
https://beej.us/guide/bgnet/

Target environment:
- FreeBSD guest VM running under QEMU
- SSH access from host
- clang, make, sbcl, emacs-nox installed

*** Phase 1: Basic socket programming inside FreeBSD VM

**** Objective
Verify basic TCP communication within a single machine.

**** Tasks
1. Write a TCP echo server in C
   - socket()
   - bind()
   - listen()
   - accept()
   - recv()
   - send()

2. Write a TCP client in C
   - socket()
   - connect()
   - send()
   - recv()

3. Run both inside the FreeBSD VM.

4. Verify communication works.

**** Success criteria
- Client sends string
- Server echoes string back

---

*** Phase 2: Host ↔ Guest communication via QEMU port forwarding

**** Objective
Communicate between host OS and FreeBSD guest.

**** QEMU configuration
Add port forwarding:

-hostfwd=tcp::4000-:4000

**** Tasks
1. Run TCP server in guest on port 4000
2. Connect from host:

nc localhost 4000

or:

telnet localhost 4000

**** Success criteria
- Host connects successfully
- Data flows both directions

---

*** Phase 3: Guest ↔ Guest communication

**** Objective
Simulate real networked systems.

**** Tasks
1. Create two FreeBSD VMs
2. Assign ports for communication
3. Connect one VM to the other

**** Success criteria
- Independent machines communicate over TCP

---

*** Phase 4: Build minimal networking runtime library

**** Objective
Provide abstraction layer for Andy language.

**** Create runtime file

andy_net.c

Functions to implement:

int andy_tcp_listen(int port);
int andy_tcp_accept(int server_fd);
int andy_tcp_connect(const char* host, int port);
int andy_tcp_read(int fd, void* buf, int size);
int andy_tcp_write(int fd, const void* buf, int size);
int andy_tcp_close(int fd);

**** Compile into runtime library

clang -c andy_net.c
ar rcs libandy_net.a andy_net.o

---

*** Phase 5: Integrate into Andy transpiler

**** Objective
Expose networking primitives in language.

**** Example target syntax

server := tcp-listen(4000)
conn := tcp-accept(server)
msg := tcp-read(conn)
tcp-write(conn, "hello")

**** Compiler responsibility
Emit calls to runtime library functions.
